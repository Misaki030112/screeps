# 指挥官接管

`Memory.cmd` 是盖在主循环上的一层临时指令。它只在武装时占住已经点名的那一只 creep，或那一座建筑，做完或到期再交还。平时的角色、实验室旗标和软顶仍由它们原来的脚本写。这一层不另写一套经济。

没武装时，主循环在逃跑之前只做一次假值判断。`Memory.cmd` 不在，或者 `on` 是假，后面的接管都不进去。这一拍在整段循环里的位置，见 [主循环](/mechanisms/loop)。

## 没武装的时候

`armed` 要两件同时成立：`Memory.cmd` 存在，并且 `on` 为真。缺一件就是没武装。

主循环因此不调用 `runHeldStructures`。每只 creep 在 `home.flee` 之前的那一次判断是假，逃跑和角色照旧。各角色开头的 `yieldCreep` 也是同一次判断，立刻返回。去问一只 creep，不会因此创建 `Memory.cmd`。它身上若还留着 `_cmd`，这一拍清掉。

实验室旗标仍是 `Memory.ops.labs` 里人设的那一个。软顶仍由原来的脚本写。这一层不写 `Memory.ops`，不写 `raidOrder`，不写 softCap，也不改角色自己的目标。

## 只占点了名的那一个

指令分两只袋子。`Memory.cmd.c` 的键是 creep 的名字。`Memory.cmd.s` 的键是建筑的 id。没出现在里面的，脚本照旧。旁边的塔、旁边的 link、同房间的另一只 creep，都不因为这一条停下来。

可以按名字写一只，也可以一次写下好几只。按角色、`kind`、家或所在房间去筛时，这四样都空，一条都不写。筛出来的仍是每只自己的一条。放开一只，不影响旁边。

把一条新指令写进袋子时，整层的 `on` 会被写成 1。想留着不执行，要再把整层关掉，或把这一条自己的 `on` 写成 0。

## 一条指令活多久

没写 `sticky` 时，缺省活 **200** 拍。`ttl` 写了正数就用那个数；没写，或不是正数，仍是 200。`until` 是数字时用写下的 `until`，否则是写下的那一拍加上 `ttl`。`sticky` 不写这两项。

自己的 `on` 是假，就不算活，清扫也不把它当过期。`on` 为真并且写了 `sticky`，就不看时钟，一直算活，旁边有 `until` 也不看。

其余的指令，`until` 是数字时，时间小于 `until` 才算活。到了 `until` 那一拍，以及之后，算过期。没有数字 `until`、但 `at` 和 `ttl` 都是数字时，用 `at` 加 `ttl` 做同一条线：小于才活，大于或等于就过期。整层还开着，过期的条目在这一拍的清扫里删掉。

开着、又不是 `sticky`、既没有数字 `until`、也凑不齐数字 `at` 和 `ttl` 的，不算活，而且算过期。整层开着时来问它，或这一拍的清扫，就删掉。

`sticky` 要离开袋子，得放开。放开一只 creep、一座建筑，或一次放开全部，删掉的是袋子里的那一条。

把这一条的 `on` 写成 0，条目留在袋子里。它不算活，也不算过期，清扫不删。`sticky` 停着也留着。打开整层不会把这一条的 `on` 改回 1。要它再执行，得把它自己的 `on` 写成真。`until` 不因为停着而改写。已经到点的非粘性指令，把自己的 `on` 写回真之后，下一次清扫会删掉，不会再跑。

整层关掉是把 `Memory.cmd.on` 写成 0。袋子还在。关掉的期间不扫过期。再打开只把整层的 `on` 写成 1，当时不删，也不改每一条自己的 `on`。下一次清扫会重新走一遍，哪怕这一拍刚才已经扫过。整层开着时，只问到一条已经过期的，也会把那一条删掉。自己的 `on` 仍为真、又没过期的，下一次来问就继续。

<CmdLife />

`once` 只在动作返回 **0**（引擎的 OK）之后放开。占住这一拍、但没有调用，或调用没有成功，都不算，指令还在。`hold` 和 `move` 已经站在写下的距离里，也算完成：这一拍仍被占住，指令删掉，下一拍才交还。

`fallback` 用在这一拍做不成的时候。有它，这一拍不算接住，逃跑和角色都会再看，指令还留着。没有它，做不成也占着，什么也不做。两种都不去房间里另找一个目标。

## 一只 creep

主循环里，解脱和停一拍在接管之前。这一拍被停掉的，指令还在，下一拍再看。顺序在 [主循环](/mechanisms/loop)。

有具体的 `act`，并且这一拍接住了：在 `home.flee` 之前就结束这只。逃跑、换位和角色都不跑。接住的那一拍，记忆里的 `_cmd` 标成 1。放开、过期，或这一拍没接住，就删掉这个标记。角色自己的键不动。

只有职责、没有 `act`：`consumeCreep` 不接。会走 `home.flee` 的那些角色仍先看逃跑。躲开了，这一拍职责不执行，指令还在。没躲开，才进角色。谁不走这个函数，见 [主循环](/mechanisms/loop)。W47 的 creep 不走它。它们的脚本开头先问 `yieldCreep`，所以职责会压过后面的回收和角色身体。

各角色都在自己的 `run` 开头问 `yieldCreep`。它先再问一次 `consumeCreep`（同一拍已经问过的，直接用上次的结果），没接住再交给 `obey`。没武装时这一问立刻返回。

### 具体动作

`act` 由 `consumeCreep` 执行。它只调用这只 creep 身上已经有的方法。

站住或走到写下的坐标：`idle`、`say`、`hold`、`move`。`say` 最多 10 个字。`hold` 没写 `range` 时要站到那一格，`move` 没写时停在距离 1。

对一个写明的 id 做事，缺省距离是 1：`attack`、`heal`、`transfer`、`withdraw`、`pickup`、`harvest`、`repair`、`build`、`dismantle`、`upgrade`。`upgrade` 没写 id 时，用这只 creep 所在房间的控制器。`rangedAttack` 和 `rangedHeal` 的缺省距离是 3，指令写了 `range` 就用那个。资源没写时按能量。`amount` 写了才限额。

`drop` 放下。`rangedMassAttack` 不另找目标。`recycle` 走向写明的出生点；没写，就用本房间第一座，挨着才回收。

不认识的 `act` 说一个问号（指令里已有 `say` 就说那句），然后看 `fallback`。没有那个方法，或没有目标，同样看 `fallback`。身上可以带 `heal: 'self'`：有治疗、又没满血，这一拍顺手给自己补。不因此去找别人。

走路仍用原来的移动。军事角色走军事移动，其余走普通 `moveTo`。跨房间时最多 16 间，同房间是 1。寻路的缓存不在这一页。见 [移动](/mechanisms/move)。

这些调用不编一份战斗身体，不 claim 控制器，也不打开安全模式。

### 职责能做的才做

`obey` 只在盖章理由是 `cmd`、并且这条指令没有 `act` 时动手。有 `act` 时它不执行职责，把这一拍留给上面的具体动作。

它会做完的职责：

- `idle`：说一句（有 `say` 才说），占住。
- `hold`、`kite`、`flee`：有坐标就走。`flee` 没写 `range` 时距离是 3，`hold` 和 `kite` 是 0。没有坐标时，`flee` 和 `kite` 朝本房间第一座出生点走，停在距离 3；找不到就交还。`hold` 没有坐标就站住。这三件不看身上有没有能量。职责里的 `flee` 是指令自己写下的那一步。`home.flee` 仍按主循环原来的名单，在职责之前先看。
- `fillSpawn`、`fillTower`、`bank`：身上没有能量就交还，让角色去捡，指令还在。有能量才送。`fillSpawn` 没写 id，就找还有空位的出生点或延伸。`fillTower` 没写 id，就找能量低于 **900**、还有空位的最近一座塔。`bank` 送进本房间的存储。找不到目的地，这一拍交还。

`focus`、`haul`、`repair`、`lab`、`upgrade` 是建议。角色脚本已经知道怎么做，`obey` 返回假，角色照跑。指令还在。

只要这条指令还活着，里面有 `act` 或 `duty`，`suppressed` 就是真，即便这一拍已经落回角色。袭击角色因此跳过自己的 `raidOrder`，其余仍按它的脚本。放开之后那张单子还在。出击不在这一页。

根上的 `steer` 只在这一拍给没有点名职责的 creep 盖一个建议，理由是 `steer`。`obey` 不执行。不写进 creep 的记忆。

## 一座建筑

出生点最先。然后是各房间：家按塔、link、实验室的顺序；W47 在塔之前先跑自己的 link，并且不进家的实验室管理器。creep 循环之前，整层若还武装着，再跑 `runHeldStructures`。没武装时这个函数不调用。塔、link、出生点不进这后一步。它们只在自己的管理器里问。同一座、同一拍、指令没换过，第二次询问直接用上次的结果。

这一拍看不见那座建筑，指令留着，不删。

### 塔、link 和出生点

塔在家和 W47 都是先把有指令的那一座摘出去。`idle` 和 `hold` 占住。`attack`、`heal`、`repair` 要写明目标 id，然后调用塔上已有的方法。没有目标，看 `fallback`。不自己挑一个目标。旁边没有指令的塔，仍按原来的治疗、射击或修理走。

link 也是一座一座问。家问的是源和枢纽，并且仍是每 3 拍才看一次；没进来的那两拍，指令留着，也不传送。W47 每拍问源 A 和枢纽。被占的那一座让开，另一座照常。控制器那座不在这两段里。传送的门槛在 [Link 与枢纽](/mechanisms/links)，这里不重讲。

`idle` 和 `hold` 占住这一拍。`transfer` 要一个目标 id。目标找不到，看 `fallback`：有它，这一拍交还自动传送；没有，就占着不送。冷却中的 `transfer` 不论 `fallback`，都占住并且不调用 `transferEnergy`。冷却不是一次成功的返回，`once` 不因此放开。

出生点正在孵的那一拍不问。整层一武装，家和 W47 的孵化闸都会把这一拍的空闲跳过打开，管理器才问得到指令。某一座上没有活指令时，自动队列仍排。有活指令，才占住这座，不排自动队列。

`idle` 和 `hold` 占住。`spawn` 只有 `allow` 为真，并且 `body` 是一份非空数组，才调用 `spawnCreep`。缺一项，这一拍仍被占住，不另编一份身体。调用了，这一拍也占住。返回不是 0 时，`once` 不放开，自动队列仍不排。没写 `mem` 就用 `{ role, v2: 1 }`，`role` 用指令里的，没有就写成 `hauler`。名字没写，用 `cmd` 加上当前时间。身体仍是那份数组。

出生点上的 `recycle` 只在点名的那只 creep 已经挨着它时才回收。还没挨着，这一拍占住出生点，creep 不会被拉过来。creep 自己的 `recycle` 才会朝出生点走。

### 后面再看的那几座

`runHeldStructures` 按袋子里的 id 看五类。观察者、核弹、工厂、Power Spawn，以及挂了指令的实验室。

观察者的 `observe` 用指令里的 `room` 字符串，不是建筑 id。不是字符串，看 `fallback`。`idle` 和 `hold` 占住。

核弹的 `launch` 只有 `allow` 为真，并且指令里已经有 `pos`（`x`、`y`，房间用 `room` 或 `roomName`），才 `launchNuke`。缺一项就等着，不发射，也不自己选一间房、一个坐标。

工厂和 Power Spawn 的执行还没写。活指令占住这一拍，函数里什么也不调用，也不调用 `processPower`。没有一次成功的返回，`once` 也不会在这里放开。

实验室分两处问。家的反应管理器在旗标开着、三座也选得出来之后才看。输出上的 `react` 先按这条指令处理，自动反应这一拍跳过。输出或任一输入上的指令若接住了这一拍，自动反应也跳过。`fallback` 让这一拍没接住时，自动反应仍往下看。这些都不改 `Memory.ops.labs`。`react` 要写明 `in1` 和 `in2`，两座都找得到才 `runReaction`。缺一座，这一拍仍被占住，反应不跑。旗标没开、或选不出那三座时，管理器在问指挥官之前就返回。没被选进这三座的实验室，以及 W47 这一拍不进 `labs.run` 的实验室，由 `runHeldStructures` 看。同一座同一拍已经执行过的，不会再反应一次。原料和那几道门在 [实验室](/mechanisms/labs)。

### 终端只是等着

`blocks` 对任何有活指令的建筑为真。现在去问它的，是 W47 把钾送回家的那一步。问到了，这一拍不送，理由记成 `cmd`。这一层不调用 `terminal.send`，也没有市场。批量、空位和地板在 [矿物](/mechanisms/minerals)，这里不重讲。家把能量送到 W47 的那一趟不读 `blocks`，见 [搬运](/mechanisms/haul)。

## 这一层不改写的

- 不写 `Memory.ops`、`raidOrder`、softCap，也不改角色记忆里的目标。接住时多出来的只有 `_cmd`。
- 不编战斗身体，不 claim 控制器，不打开安全模式。出生点没有 `allow` 和一份写明的 `body`，就只是占住，不孵。
- 不自己挑攻击目标，也不自己挑核弹的落点。做不成时要么占着，要么按 `fallback` 交还。
- `steer` 只盖一个建议。职责里做不了的那几件，也只是建议。角色脚本还是原来的那份。
- 到期、`once` 成功、`release`，或整层关掉，单位交还原来的脚本。指令没删掉的，下一拍还在。
