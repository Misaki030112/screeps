# 部署

游戏要的是一层模块，名字用点连起来。`scripts/build.js` 把 `src/**/*.js` 写成 `dist/` 里的这些文件，并把相对 `require` 改成摊平后的名字。Screeps 的用户代码接口收的是这张表。检查不过，后面两条上传都不会把模块传上去。

令牌只留在执行上传的那台机器上，不进仓库。

## 摊平

`scripts/build.js` 会走进 `src/` 的子目录，只收集 `.js`。每次先清空 `dist/`，再整份重写。斜杠换成点，扩展名去掉：`src/roles/queen.js` 变成 `dist/roles.queen.js`，模块名是 `roles.queen`。`src/main.js` 仍叫 `main`，游戏入口还是这个名字。跑完之后，`dist/` 里只有这一次写出的模块。删掉的源文件，下一次成功的构建不会再写出对应模块。

只改写一种 `require`：引号里的路径以 `./` 或 `../` 开头。`src/roles/queen.js` 里的 `../utils/move` 会变成 `utils.move`。目标不在 `src/` 里，包括路径指到目录外面，构建当时就抛错。其他写法的 `require` 原样留在文件里，构建不去找它的目标。

构建中途抛错，`dist/` 可能只写了一部分。检查会停。两条上传都不会把这半份传上去。

## 检查

`node scripts/check.js` 按这个顺序做四件事。前面一步失败，后面的不跑，上传也不会开始。

1. 重新执行 `scripts/build.js`。
2. 对 `dist/` 里每个文件做语法检查（`node --check`）。看的是摊平之后的文本能不能解析，不执行模块。
3. 调用 `node scripts/sim.js 600`，用存档快照把家的循环跑 **600** tick。
4. 按 `check.js` 里写好的顺序，逐个跑 `tests/` 下的那些文件。

### 模拟不只要循环跑完

模拟读仓库里的 `data/sim_snapshot.json`，地形用 `data/terrain_W46N8.txt`，房间固定是家 **W46N8**。快照和地形都随仓库走。检查不去连 shard3。快照会过时，大改之前应该换成当时的房间。

循环抛出的异常，以及被收进统计的错误，都会让这次模拟失败。除此之外还有四道门。

- 快照里一开始就在、模拟结束时还在的 creep，600 tick 里模拟记下的行动少于 **50** 次的，多于 **2** 只就失败。这一轮新出生的不计入。
- 日志里要有布局管理器写下的一行（以 `LAYOUT` 开头）。没有，就当作这一轮布局什么都没做。房间已经和规划一致、无事可记时，这道门也会失败。
- 只看这一次模拟里的第一只出生。角色名不是 `queen` 或 `filler`，出生格又落在家的延伸印章上，就失败。印章是 `src/layouts/W46N8.js` 里的 A、B、C，整张印章上的格子都算，不只有延伸那一格。后面的出生不看这道门。印章里外怎么选，见 [孵化](/mechanisms/spawn)。
- 跟踪写在记忆段 **90**。这一段缺失，或者读不出角色的状态码，就失败。长度要大于 **100**，并且小于 **90000**，出了这个范围也失败。

这些门看的是这份快照。下一小时的经济不在这次模拟里。

### 测试是写好的一串

单元测试是 `check.js` 里按文件写死的一串调用，顺序就在那个脚本里。在 `tests/` 新加一个文件，不会自动被跑到。

它们碰的是纯逻辑。身体和地板、外矿状态机、防御状态机、孵化闸、走不出的孵化格、实验室搬运、[指挥官](/mechanisms/commander)，都在这串里。这里不列文件名。

## 上传

两条路在把模块传上去之前，都先跑 `node scripts/check.js`。检查失败就中止。没过检查的代码不会成为 shard3 上的那份模块。

两条路用的令牌都只留在执行上传的那台机器上，不进仓库。仓库、手册和这个网站都不包含它，也不包含任何控制台密码。

### `node upload.js`

后面可以跟一个参数，当作游戏里的代码分支名。不跟参数时，分支名是 `default`。这是游戏分支，不是 git 分支。检查通过之后，才读取那台机器上的令牌，把 `dist/` 里每个文件收成一张模块表传上去。表的键是文件名去掉 `.js`，也就是摊平时的点名。

### `python3 scripts/deploy.py`

同样先检查，检查失败就中止。分支写死为 `default`，没有可以改分支的参数。它在检查之前拿一把锁，避免两次 `deploy.py` 同时上传，并留下一条上传记录。`node upload.js` 不经过这把锁。

### 先提交

摊平和检查读的都是磁盘上的 `src/`，不是某一次 git 提交。没提交的改动也能过检查，也会被传上去。线上当时跑的代码就可能对不上任何一个提交。人应该先提交，再上传。

### `dist/` 不进仓库

根上的 `.gitignore` 忽略了 `dist/`。它是构建产物。克隆下来的仓库里没有它。要得到和当前 `src/` 相同的摊平结果，先跑检查。检查的第一步会重新构建。同一份源码得到同一份模块。

## 为什么检查要先于上传

摊平后的一个错误 `require` 会在游戏里变成整拍脚本失败。房间会停在上一份代码上，或者更糟，停在一套半新的模块上。相对路径对不上文件时，构建已经抛错，检查不会通过，这一种错误到不了游戏里。

语法检查抓笔误这一级的错误。单元测试抓地板、身体，以及防御状态机、孵化闸、走不出的孵化格、实验室搬运、指挥官这一类纯逻辑的回归。模拟抓的是「这份家的快照至少能跑」，并且空转、布局、第一只出生的格子和跟踪段那几道门也要过。它们都不证明下一小时的经济是健康的。那是上传之后的事，不写进这个站点。

## 这本手册怎么单独发布

手册是仓库里的 `docs-site/`，用 VitePress 做成静态站。根上的 `vercel.json` 在导入整个 Git 仓库时只安装、只构建这个目录：安装是 `npm ci --prefix docs-site`，构建是 `npm run build --prefix docs-site`，输出 `docs-site/.vitepress/dist`。游戏代码没有根上的 `package.json`，不会被当成网站去编译。

网站不需要环境变量。没有令牌、没有数据库、没有内网地址。房间名和上面这些机制是公开的游戏设计。

公开地址是 [https://screeps-handbook-nolove-world.vercel.app](https://screeps-handbook-nolove-world.vercel.app)。

本地预览：

```bash
cd docs-site
npm ci
npm run dev
```

构建：

```bash
cd docs-site
npm run build
```
