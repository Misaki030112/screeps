# Link 与枢纽

Link 把一段方向固定的路换成一次传送。冷却取两座 link 横差和竖差里较大的那个，送得少也要等完这段冷却。每次传送扣 **3%**。家和 W47 都用它把能量送到控制器旁边。节拍、出手线，以及「这一拍没有目标时能量去哪」，两间房各写各的。

<LinkFlow />

升级工只数在 [升级](/mechanisms/upgrade)。谁把存储灌进枢纽、搬运工地板是 2 还是 3，在 [搬运](/mechanisms/haul)。这一页只写传送顺序和把门的那些数。

## 两种节拍

`main.js` 对家每拍都调用 `managers/links.js` 的 `run`。函数开头是 `Game.time % 3`：余数不是 0 就立刻返回。所以真正看 link 的是时间能被 3 整除的那一拍。link 自己的冷却仍按距离算。冷却在两次查看之间结束，最多再等 2 拍，脚本才会把它送出去。房间里的 link 不到两座，这一拍也不送。

W47 不走这个函数。`main.js` 进了 W47 就只跑布局和 `towerRun`，然后 `continue`。`linkRun` 写在 `towerRun` 的第一行，塔还没找到就先看 link，所以没有塔的那一拍也送。它每拍都看，不等 3 拍。

## 家

`STATIONARY_FILL` 现在是 false。link 的格子不跟 v2 布局稿走，只跟 `plan.LINK_PLAN`。稿子里 RCL5 还有一座 35,26；关着这面旗时，那一格要到 RCL8 才进计划。

| 名字 | 坐标 | 计划中的 RCL |
| --- | --- | --- |
| 枢纽 | 37,29 | 5 |
| 控制器 | 30,31 | 5 |
| 源 A | 30,11 | 6 |
| 第四座 | 32,34 | 7 |
| 第五座 | 30,25 | 8 |
| 第六座 | 35,26 | 8 |

`roles()` 按格子认建筑。枢纽是 37,29，控制器是 30,31。固定 filler 关着，`fillers` 是空数组。其余已经立起来的 link 都算源，包括计划里 RCL7、RCL8 那三座，如果它们已经在。它们跟着源一起送，不会被当成 filler 来灌。

### 源先送，枢纽不退回

常数是 `CTL_LOW = 400`、`SEND = 400`。够了就把这座 link 里的能量送出。一次送多少，看里面有多少、对方还剩多少空位。400 只决定要不要动手。

目标按这个顺序取，取到就停：

1. `noUpgrade` 为假，而且控制器 link 的能量低于 400：目标就是它。
2. 否则，能量最低、并且低于 400 的 filler link。现在没有 filler link，这一条是空的。
3. 再没有，目标就是空。

源的循环先跑。一座源不在冷却、能量至少 400、也没被指挥官占用，就送。这一拍有目标，送给目标。这一拍没有目标，改送枢纽。枢纽的循环在源后面。枢纽能量至少 400、不在冷却、也没被占用时，再读一次目标。目标还在，才送。目标是空，枢纽留着。枢纽不会把能量送给自己。

所以控制器 link 已经不低于 400 时，源仍会把多出来的能量退进枢纽，枢纽自己不再往外送。同一拍里源先改库存。源把控制器补到 400 或以上之后，枢纽接着读到的是送完的数，这一拍就不再补。

源 A 到控制器 30,31，横差 0、竖差 20，冷却 **20**。源 A 到枢纽，横差 7、竖差 18，冷却 **18**。枢纽到控制器，横差 7、竖差 2，冷却 **7**。家这三段里，枢纽到控制器最短。

### 能量怎么进枢纽

源 A 的矿工站在 **31,12**。身上有携带容量，而且空位小于 WORK 数的两倍，就把能量送进旁边的 30,11。源 B 站在 **38,32**，旁边是存储 **37,31**，计划里没有源 B 的 link，矿工直接送进存储。

房间已经满了，女王才做 link 这段待机：可用能量到了容量，而且没有一座塔低于 **900**。允许升级时，控制器 link 低于 400、枢纽还有空位，她把存储里高出 `storageFloor` 的那一截送进枢纽。存储没有高出地板的部分，她不从存储抽。控制器 link 并不低、控制器容器却低于 **1000** 时，她改去补那只容器。地板怎么算、容器那条怎么排，在 [搬运](/mechanisms/haul)。

`noUpgrade` 为真时，控制器 link 退出目标。源里至少 400 的能量退进枢纽，枢纽不再送出。家的搬运工改到管理者站位 **36,30** 等，这一格同时挨着枢纽和存储。枢纽里至少有 `min(空位, 400)` 才取走，见 [搬运](/mechanisms/haul)。女王手里是空的、枢纽能量多于 400、房间里又没有家的搬运工时，才由她把枢纽抽出来，免得能量停在 link 里。抽出来之后走平时的补能，见 [搬运](/mechanisms/haul)。哪些阶段会让 `noUpgrade` 为真，见 [升级](/mechanisms/upgrade)。

## W47

源 A 的矿在 **27,11**，矿工站 **26,11**，link 在旁边的 **26,12**。控制器 link 在 **13,25**。枢纽 link 在 **32,33**，紧挨枢纽容器 33,33。`layout.hubLinkPos()` 取计划名单里的第一座 link；那一格如果是已经退掉的旧位置，才回落到 32,33。现在名单上就是 32,33。

源 B 的矿在 **11,44**，站位 **11,43**。配置里没有 link。只有源 A 走传送，源 B 仍由搬运工从容器拉走。见 [搬运](/mechanisms/haul)。

### 源 A 看空位，枢纽看 400

`linkRun` 先看源 A，再看枢纽。两座的冷却分开计，同一拍可以都送。指挥官占用其中一座时，另一座照常。

源 A 不在冷却、也没被占用，而且里面至少有 **50**、控制器 link 的空位大于 0，就送出 `min(已有, 空位)`。控制器 link 里已经有多少，这段不看。控制器已经不低于 400 时，源 A 只要还有空位也送。

枢纽要同时满足：建筑在 32,33（不是源 A 那一座），不在冷却，没被占用，控制器 link 的能量低于 **400**，枢纽里至少 **200**，控制器还有空位。送出的同样是 `min(已有, 空位)`。控制器已经不低于 400，枢纽这一拍留着。枢纽低于 200，也不送。

注释里记过一次死锁：若还要求控制器空位至少 400，控制器停在大约 486、空位只剩 314 时，源 link 会一直满着。现在的代码不设这道空位门槛。50 是避免一次只送一点点、却付掉整段冷却。

源 A 到 13,25，横竖都差 13，冷却 **13**。枢纽 32,33 到 13,25，横差 19、竖差 8，冷却 **19**。

### 满载时每拍大约 40.8

一座 link 按 **800** 计。枢纽这段若每次冷却都送满，毛输送是 800÷19，大约每拍 **42.1**。扣掉 3% 之后到达 **776**，776÷19 大约每拍 **40.8**。源码注释写成大约 42 毛、大约 41 净，升级页沿用了大约 41。这是满载上限。枢纽还要控制器低于 400、自己至少 200，所以不是每 19 拍都送得出这一整份。

按升级页现在的目标，是两只、每只 10 个 WORK。满载时这条管子够喂。link 通了也不把升级工的闩松开。只数、座位，以及再加一只时管子够不够，写在 [升级](/mechanisms/upgrade)。

### 旗标只放工地

`HUB_LINK` 现在是 true。它只决定布局要不要把 32,33 放进工地名单。升级上限和回收看的是 `hubLinkLive`：旗标开着，并且 32,33 上已经立着这座 link。只开旗标、工地还在造，`hubLinkLive` 仍是假，升级上限不抬。若只看旗标就把升级工加上去，控制器会在 link 还送不出能量的时候断粮。

**33,34** 是 `RETIRED_HUB_LINK`。它已经回到路，夹在枢纽容器 33,33 和塔 33,35 中间。站在那里的 link 不发送，filler 不灌它，`hubLinkLive` 也不认它。布局会拆掉这一格上的 link 工地，不拆已经建好的建筑。旧建筑还在时，32,33 先不放第二座。注释写明 RCL7 还有一个 link 名额，提前放下就会留下两座枢纽。路和 rampart 可以和 32,33 的 link 叠在同一格，别的建筑会挡住工地。

### 北塔低于 600 时，矿工让开 link

源 A 的矿工有携带容量，而且空位不超过身上 WORK 的两倍，link 还有空位，就把能量送进 26,12。有一个例外。站位 26,11 四格以内、能量低于 **600**（`NORTH_FEED`）的己方塔，加上脚下容器低于 **1500**，这一拍不送 link。收获溢出进容器 26,11，搬运工再从这里送到近处的塔。北塔 **24,8** 到站位的距离是 3。RCL7 的塔 **22,7** 距离是 4，立起来并且低于 600 时同样算。塔回到 600，或者容器已经到 1500，矿工继续送 link。塔或源 link 还没立起来时，这段不发生。搬运工怎么给这只容器加分，在 [搬运](/mechanisms/haul)，这里不重写打分。

北源 link 已经立着、能量预算至少 **750** 时，`bodyFor('w8miner')` 给矿工加 1 个 CARRY。判断只看源 A 那座 link，两只矿工共用。身体公式在 [孵化](/mechanisms/spawn)。

升级工站在座位上，不走进 13,25。挨着这座 link、身上能量低于 WORK 的两倍时，可以从它取出。家的升级工则是身上能量不多于 WORK 数时，先取控制器 link，link 没有能量再用容器。座位在 [升级](/mechanisms/upgrade)。

枢纽这边没有别的活时，filler 才把存储灌进 32,33。存储至少要到 `LEAN_ARM` **15000**。还没到 **25000**，只在枢纽低于 200 时预热。到了 25000，控制器电池薄的时候也灌。人怎么走、电池的 800 和要留的空位，在 [搬运](/mechanisms/haul)。

`Memory.ops.w8model.links` 为真时，本地搬运工的地板是 **2**，否则是 **3**。这个键不决定 link 送不送。只数在 [搬运](/mechanisms/haul)。

## 为什么家是 400，W47 的源是 50

家的 `SEND` 和 `CTL_LOW` 都是 400，是 800 的一半。冷却按整段距离算，送得太少也要等那么久，所以家把出手线放在半座 link。W47 的枢纽用 **200**。注释写的是让断断续续的电池早点恢复。家的枢纽仍用 400。

W47 源 A 的 50 是另一道门。注释写明它用来避开零碎的小传送。这段距离是 13。家的源到控制器是 20，家的枢纽段是 7，W47 的枢纽段是 19。这几个距离决定冷却。50 比 400 低，是为了少做一次只送一点点的传送。

## 指挥官占用

`Memory.cmd` 开着，而且这座 link 上有活指令时，`consumeLink` 为真，自动传送让开。`idle`、`hold` 占住这一拍；`transfer` 改由指令指定的那一次传送执行。没开指挥官时，这段判断不改变传送。指挥官怎么下指令，不在这一页展开。
