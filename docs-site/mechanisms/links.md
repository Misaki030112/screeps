# Link

Link 把「走路」换成一次冷却后的传送。冷却和距离有关，所以 link 只值得用在重复、方向稳定的那几段：源到控制器，存储到控制器。不值得用在「看看这拍谁饿了」。

## 家的方案 A

`STATIONARY_FILL` 关着的时候，link 的位置不跟旧布局稿走，只跟 `plan.LINK_PLAN`：

| 名字 | 坐标 | 计划中的 RCL |
| --- | --- | --- |
| 枢纽 | 37,29 | 5 |
| 控制器 | 30,31 | 5 |
| 源 A | 30,11 | 6 |
| 第四座 | 32,34 | 7 |
| 第五座 | 30,25 | 8 |
| 第六座 | 35,26 | 8 |

`managers/links.js` 每 3 tick 看一次，省 CPU。源 link 和枢纽 link 在自己至少有 **400** 能量、而且没在冷却时，才传送。目标优先是控制器 link，如果它低于 **400** 并且现在允许升级。否则在固定 filler 打开时才会去喂 filler 的 link；那套关着，所以没有就退回枢纽。

枢纽里的能量从哪来：女王在房间已经补满、存储又高于地板时，把多余能量倒进枢纽。源 A 的矿工则直接把能量送进身边的 link。这样控制器旁的升级工不需要一只搬运工专门跑完整条对角线。

墙如果进入「暂停升级」的阶段，控制器 link 不再当目标。源的能量会堆在枢纽里。这时家的搬运工改到枢纽旁边等，避免女王为了疏通枢纽离开它该补的那一片延伸。

## W47

源 A 的 link 在矿工站位 26,11 旁边（26,12）。它在里面至少有 50、控制器 link 还有空位时就送去 13,25。这一段短，所以门槛比家低，免得源容器先满出来。

枢纽 link 在 **32,33**，紧挨枢纽容器 33,33。配置旗标 `HUB_LINK` 是 true，但升级是否放开，看的是这座建筑在不在，不是旗标。旗标只能放下工地。工地还在时就把升级工加上去，控制器会断粮。33,34 是已经放弃的旧位置，站在那里的 link 不算数。

枢纽向控制器送的条件是：控制器 link 低于 400，枢纽里至少有 200。距离大约 19，冷却也大约是这个量级，毛输送大约 40 能量每拍，扣掉损耗后仍够现在这两只 10 WORK 的升级工，不够突然多出来的一排。所以 link 通了也不等于可以把升级工加倍。数量的闩在 [升级](/mechanisms/upgrade)。

Filler 负责把存储送进枢纽 link，而且存储要至少 15000。这和家的女王待机是同一件事：link 传送的是地板以上的能量，不是底火。

## 为什么家是 400，W47 的源是 50

家的源 link 到枢纽或控制器都要付一次完整传送，传太少就在付冷却。400 大约是半座 link，值得动一次。W47 的源就在矿旁边，容器很小，50 是「别让矿工无路可倒」的下限。两个数字都是在避免空转，不是谁抄谁。

指挥官可以占用某一座 link。占用期间自动传送让开。没开指挥官时，这段检查不改变行为。
