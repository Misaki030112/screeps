# 主循环与 CPU

Screeps 每个 tick 调用一次 `loop`。这一拍先让出生点、塔和补能还活着，再把时间交给挖矿和升级。顺序写在 `src/main.js`。桶不低于 2000 时，creep 按 `Game.creeps` 的原顺序跑完。桶低于 2000 时，战斗和补能排到经济前面；经济单位可以整只停一拍，免得脚本在防御还没跑完的时候被掐断。

掐断会停在任意一行。防御 creep 可能已经开头、还没迈步，末尾的统计也可能没写上。停一拍是让这一只 creep 的意图空过。存储和容器扛得住晚一点去捡。塔这一拍没打、出生点这一拍没补上，下一拍补不回来。

身体怎么长在 [孵化](/mechanisms/spawn)。link 的门槛在 [Link 与枢纽](/mechanisms/links)。反应在 [实验室](/mechanisms/labs)。外矿三条线在 [外矿](/mechanisms/remotes)，状态机在 [防御](/mechanisms/defense)。这一页只排顺序。

## 为什么先建筑，后 creep

出生点和塔在 creep 之前跑。它们用的是上一拍已经送进建筑里的能量。这一拍把能量送进出生点和塔，要等 creep 段的女王和 `w8filler`。桶不够分时，先让能开枪的人动，再让下一拍还有能量可打，经济排在这两件事后面。

外矿的状态机也在 creep 之前。矿工和搬运工这一拍读到的，是刚刚写下的状态。家的两条矿的警报放在管理器之后，原因写在下面那一节。

## 记忆、孵化、然后才是房间

循环先读一次 `Memory.creeps`，再删掉已经不在 `Game.creeps` 里的名字。

然后是出生点。房间名是 W47N8 的，进 `rooms/w47n8` 的 `spawnRun`。其余进 `managers/spawn`。谁先于谁孵，写在 [孵化](/mechanisms/spawn)。这里只分清两个入口。正在出生的 creep 到了后面的 creep 段会整只跳过：不解围，不停一拍，也不跑角色。

## 已占领的房间分成两支

房间扫描看两件事：有控制器，并且 `controller.my`。两件都成立，才算我们的房间。外矿只有预定，没有所有权，这一支整段跳过。

### W47 是单独的一间

`rooms/w47n8` 开头写着：只为 W47N8 跑，家 W46N8 的代码看不见它。主循环见到这间房，只跑它自己的 `layoutRun` 和 `towerRun`，然后 `continue`。家的 `links.run`、`labs.run`、`alerts.run` 都在 `continue` 后面，W47 到不了。

`towerRun` 的开头按这个顺序：先 `mark` 本房，再 `mark` 配置里的 W47N7。这一拍看不见 W47N7，第二次调用拿到空房间，直接返回。然后是 `linkRun`，然后才去找塔。没有塔的那一拍，link 已经看过。`linkRun` 不是主循环里的另一步。传送的门槛在 [Link 与枢纽](/mechanisms/links)。`mark` 记下什么，在 [防御](/mechanisms/defense)。

实验室不在这支里，是因为主循环没有把 W47 送进 `labs.run`。`labs.js` 写的是家的反应：文件开头的三座坐标是 W46N8 的 34,22、33,21、35,21，`readyObs` 只在房间名是 W46N8 时记清单。`run` 按 `Memory.ops.labs` 里这个房间名去取化合物，函数体内没有一行因为房间是 W47 就返回。W47 的布局另有一道 `RCL6_LABS`，现在是 false，规划器这一拍不把实验室放进工地。反应的门槛，以及人已经放下的实验室，见 [实验室](/mechanisms/labs)。

### 家和其他属于我们的房间

不是 W47 的已占领房间，按这个顺序：布局、塔、`links.run`、`labs.run`、`alerts.run`。家的 link 每拍都调用；时间除以 3 的余数不是 0，函数立刻返回，真正去看是能被 3 整除的那一拍。两间已占领的房间谁先谁后，跟着 `Game.rooms` 的键，源码不另排。

## 外矿的警报为什么在后面

`remote.run()` 把每条线的状态机走完。状态不在 SAFE，并且这一拍刚刚离开、或时间能被 50 整除时，管理器自己打一行 `ALERT`。回到 SAFE 时打结束。那是暂停和恢复，发生在管理器里面。

外矿之后是家往 W47 送能量的 `export.run`。时间不能被 5 整除就直接返回。什么时候真的发出 5000，见 [搬运](/mechanisms/haul)。

道路紧跟在这之后。家这一拍看不见，或者控制器不是我们的，或者等级低于 6，道路函数直接返回。铺哪一段，不在这一页。当前 RCL 的建筑位不再铺成路，第六座塔 **40,23** 因此让出来，见 [布局](/mechanisms/layout)。

道路之后，主循环再扫一遍看得见的房间，只对 `remote.CFG` 调用 `alerts.run`。CFG 是家在挖的 **W45N8** 和 **W45N7**。W47N7 在守卫表里，不在 CFG 里：状态机在 `remote.run()` 里已经走了，这段扫描不再进那间房。W47N8 自己也没有 `alerts.run`，它的记号在 `towerRun` 的 `mark`。

家的警报在第一段房间扫描里，外矿管理器之前。等在后面的，只是 CFG 这两间。外矿进不了「控制器属于我们」的那一支，只能凭这张表再认一次。管理器先把这一拍停不停、要不要防御 creep 写完，扫描再记矿上的敌人和掉血。`alerts.run` 不读刚写下的状态。它每拍看敌对 creep 和事件日志里的攻击，建筑血量差每 **5** 拍做一次。两段各自包在错误处理里。管理器抛错，这段扫描仍会跑。

## 桶：2000、停一拍、以及 3000

这一账号在 Shard3 上，每 tick 的限额是 **20**。源码不写死 20，也不自己裁到 20。它读当场的 `Game.cpu.tickLimit` 和 `Game.cpu.bucket`。桶是没用完的限额积下来的储备。游戏里的上限是 10000，这份代码不读那个上限。

平时一拍用掉几单位，桶是满的，creep 按原顺序跑完。桶降下来之后，若仍让每只 creep 都找一次路，战斗那一拍会把储备掏空，后面很多拍都在还。经济晚一拍去捡，容器还在。防御和补能晚一拍，这一拍就空了。

<CpuOrder />

数在 `src/utils/cpuorder.js`。`LOW` 是 **2000**，`MARGIN` 是 **5**。

桶 **不低于** 2000，`order` 返回 `Object.keys(Game.creeps)`，不按角色重排，`shed` 也是假。这一拍即使已经用得很满，代码仍让后面的 creep 继续跑。引擎仍可能把脚本掐在半路。2000 这道门是在储备已经薄的时候才打开的。

桶 **低于** 2000，两件事一起发生。

顺序改成优先级从小到大。同优先级保持原来的先后。0 是战斗，1 是补能，其余是 2。补能这一档只有两个角色名：`queen` 和 `w8filler`。家里补延伸的是女王，W47 枢纽这一侧是 `w8filler`，见 [搬运](/mechanisms/haul)。角色名 `filler` 不在表里，落到 2。

`shed` 为真，要三件同时成立：桶低于 2000，优先级大于等于 2，并且这一拍已经用掉的 CPU **大于** `tickLimit - 5`。剩下的额度小于 5，这一只才停。剩下正好 5，还跑。优先级 0 和 1 永远不停，哪怕已经贴着限额。停掉的是这只 creep 剩下的全部意图，包括寻路。这一拍不为它重算路，也不会因为它没走动就记成卡住。路径怎么缓存，不在这一页。见 [移动](/mechanisms/move)。

外矿防御另有一道桶，和 2000 不是同一个数。`threat` 的 `minBucket` 是 **3000**。`gateReason` 在已经武装、并且 `Game.cpu.bucket < 3000` 时返回 `cpu`。武装没开时先返回 `gate`，轮不到这道 CPU。从 SAFE 出发，本来要进入 THREAT 的单人、守卫或核心，改为 WAIT，理由是 `cpu`，这一拍不新开一场去要那只防御 creep。已经在 THREAT 或 DEFEND 里的，要不要再孵看状态和名额，不再读这道桶。停在 `cpu` 上的等待，要 `gateReason` 不再返回理由，并且种类仍是单人、守卫或核心，才回到 THREAT。桶回到不少于 3000 是其中一件。其余的闸在 [防御](/mechanisms/defense)。

有人习惯把桶留在 **5000** 以上，给突然进来的人留余量。`cpuorder` 和这道 3000 的闸都不读 5000。

## 每只 creep 里面

桶低于 2000 时，上面的顺序先排好，再逐只进入。每只里面仍是同一条窄路。

1. 正在出生的，跳过。
2. `queen.freeTrapped`。任何角色都看。这一格还有能走出去的邻居，函数马上返回，继续往下。走不出去时，这一拍只做第一件做得成的事：身上还有空位，就捡脚边一格内的能量；身上有能量，就送进旁边还空着的出生点、延伸或塔；旁边有空闲出生点就回收；出生点正在孵就等着；否则自杀。做了这件事，这一只结束，角色脚本不再跑。
3. `shed`。为真则这一只结束。寻路和角色都不跑。
4. 没有 `role`，写成 `harvester`，避免空记忆的单位什么都不做。
5. 还没有 `v2`，删掉旧键 `spot`、`_move`、`_m`、`src`、`dst`、`t`、`sink`、`stop`、`repairId`，再标上 `v2`。这是一次性的迁移。被停一拍跳过的那一只，这一拍还不会改这些键。
6. `Memory.cmd` 武装，并且 `consumeCreep` 接住了这只：逃跑和角色都不跑。没武装时，这里是一次假值判断。
7. `home.flee`。躲开了，角色不跑。
8. 军事换位若已经点了这只平民的名，改走那一步。否则跑角色脚本。表里没有这个角色，仍用 `harvester`。

解脱放在停一拍之前。停一拍会把后面的意图整段跳过。走不出去的格子若也跟着跳过，这只 creep 会再站一拍，能量还锁在身上，出生点也腾不出来。解脱是就地的动作，不寻路，所以桶低时仍先做。走得出去的，这一步几乎不花时间，再交给后面的 `shed` 决定跑不跑角色。

### 谁不逃跑

`home.flee` 只在控制器属于我们的房间里看。主循环传入的距离是 **4**（函数自己的缺省是 5）。4 格内要有带着攻击或远程、而且部件还活着的敌人。治疗不算。找得到一步，就迈出这一步，这一拍不再跑角色。

这些角色不调用它：`guard`、`defender`、`probe`、`raid9`、`cqsquad`、`cqbreaker`、`cqworker`、`cqquad`、`cqhauler`、`cqatk`、`cqminer`、`reserve7`、`cqrh`。`memory.home` 是 W47N8 的，不论角色，也不调用。W47 外矿自己的躲避在 [外矿](/mechanisms/remotes) 和 [防御](/mechanisms/defense)，不走这一个函数。

这张逃跑名单和优先级不是同一张。`probe`、`cqworker`、`cqhauler`、`cqminer`、`reserve7`、`cqrh` 不逃跑，优先级仍是 2，桶低而且贴着限额时一样可以停一拍。

### 换位

优先级 0 的那一批，也是军事移动里会要求平民让开的那一批。战斗 creep 先跑的时候，可以请旁边的平民站到自己脚下。平民自己的脚本若还跑得到，开头就改走这一步，角色不跑。平民若已经被停一拍、脚本没跑，所有 creep 结束之后仍会再发一次这步：后写的移动会盖掉先写的。战斗角色之间不这样拉。让路的代价和占格，见 [移动](/mechanisms/move)。

### 指挥官只占已经点名的那一只

`Memory.cmd` 的 `on` 为真，才算武装。武装时，creep 循环之前先跑 `runHeldStructures`：观察者、核弹、工厂、Power Spawn，以及挂了指令的实验室。塔、link、出生点在各自的管理器里已经看过指令。没武装时，这次判断是假，函数不调用。

单只 creep 上，`consumeCreep` 接住了，就不再逃跑，也不再跑角色。动作、职责，以及建筑各自等在哪一拍，见 [指挥官接管](/mechanisms/commander)。

袭击旗标在 creep 循环之前收一次，包在自己的错误处理里。哪怕每只袭击 creep 这一拍都被具体指令占住、角色脚本没跑，这次仍会跑。它只改小队记忆，不移动 creep。出击步骤不在这一页。

## 结尾不指挥下一只

全部 creep 之后：先把换位锁上，再收能量账和跟踪，然后统计，然后报告。这些都不挑选下一只 creep 去哪。

收能量账分成两处。循环一开头调用 `ledger.wrap()`，把记账包到方法上。模块里的 `done` 为真之后再调用，就直接返回，所以每个 global 只包一次。方法照常先执行。返回值是 `OK`，才加上一笔。`spawnCreep` 带了 `dryRun`，即使返回成功也不加。加上去的那一下包在 try/catch 里。记账抛错，原来的 `OK` 仍交回调用者。

换位的 `flush` 之后才调用 `ledger.tick()`。这一次只处理能量源上的浪费。它包在 `utils/errors` 里，和换位、跟踪、统计、报告同一层。开头的 `wrap` 在这一层之外。成功回调另有自己的 try/catch。

<LedgerWhen />

账本是 `Memory.ledger`。第一次写下时是 `{ t0, r, s }`。`t0` 是建账那一拍的 `Game.time`，以后不改。主循环每拍不清空，数字从那一拍起一直累加。`r` 的键是房间名，下面是分类和能量。`s` 的键是能量源的 id。每一行四个数：源所在的房间，挖到的能量，再生前浪费的能量，以及遇上再生前最后一拍的次数。第四格要等第一次遇上这种一拍才出现。

### 成功的意图记在哪

挖矿写在 `s` 的那一行。目标要有 `energyCapacity`。矿物没有这个字段，成功的矿物收割不加。`Memory.ledger` 还不在时，这次收割也不加。挖矿不创建账本。孵化、建造和其他成功意图会在第一次加上时把账本建出来，结尾的 `tick` 也会建。账本在了以后，成功的收割把还活着的 WORK 的 **2** 倍，和源上还显示的能量，取较小的那个，加进第二格。第一格是源的房间。人在外矿里收割，第一格同样是那座源的房间。

数目取的是调用返回时，对象上还显示的部件、能量和进度。同一拍里引擎还没结算，这些数不会因为更早的意图先变小。两只矿工收同一个源，两笔都按源上当时的能量封顶，加起来可以高于这一拍真正挖出的。

其余成功意图进 `r`。要加的数是 0，这个分类就不写。`home` 是 `memory.home`。没写，就用 creep 此刻的房间。

| 分类 | 房间键 | 加上多少 |
| --- | --- | --- |
| `up` | creep 此刻的房间 | 还活着的 WORK，和身上的能量，取较小的。这一笔是花掉的能量 |
| `b` | home | WORK 个数的 **5** 倍、身上的能量、工地还差的进度，三者取最小。一点进度花一点能量 |
| `rw / rr / rc / ro` | home | 还活着的 WORK，和身上的能量，取较小的。城墙和城门是 `rw`，路是 `rr`，容器是 `rc`，其余结构是 `ro`。creep 的房间和 home 不同时，分类名加上 `@` 和那个房间 |
| `sp:角色` | 出生点的房间 | 身体造价之和。MOVE 50，WORK 100，CARRY 50，ATTACK 80，RANGED_ATTACK 150，HEAL 250，CLAIM 600，TOUGH 10。没有角色名时分类是 `sp:?`。`dryRun` 不加 |
| `rf:角色` | 出生点的房间 | 回收估算。没有角色名时是 `rf:?` |
| `tw / tr` | 塔的房间 | 修理成功一次加 **10**。城墙和城门是 `tw`。路、容器和其他结构都是 `tr` |
| `th` | 塔的房间 | 攻击成功或治疗成功，一次加 **10**。两件事共用 `th` |
| `dr` | creep 此刻的房间 | 丢掉的能量。没写数量，就按身上全部能量。能量以外的资源不加 |
| `lk` | 发出的房间 | 数量乘 **0.03**，再向上取整 |

建造和修理记在 home。升级和丢能量记在 creep 此刻的房间。孵化、回收、塔和 link 记在那座建筑自己的房间。在 W45N8 修路、home 是 W46N8 时，分类是 `rr@W45N8`，房间键是 W46N8。

血还差很少的修理，仍按 WORK 和身上能量里较小的那个来加。建造会停在还差的进度上。

回收的数在调用之前就算好，返回 `OK` 才加。每个部件先取造价和 **125** 里较小的：远程 150、治疗 250、CLAIM 600 都收成 125，更便宜的保持原价。相加后乘以寿命比例。比例是剩下的 `ticksToLive` 除以上限，并且不超过 1。身体里有一块 CLAIM，整具身体的上限是 **600**，否则是 **1500**。乘完向下取整。身上带着的能量不在式子里。一具 WORK、CARRY、MOVE，寿命还满，是 **200**；还剩 749 拍时，200 × 749 / 1500 得到 99.866，记 **99**。一块 CLAIM 加一块 MOVE，寿命还满，是 **175**。

link 记的是损耗：数量乘 **0.03**，再向上取整。没写数量，就用这座 link 里现有的能量。家的自动传送不写数量，**400** 只决定出不出手，乘的是当时的全部能量。对面装不下全部，用的也是这个全部能量。按这个式子，100 记 **3**，50 记 **2**，1 记 **1**。W47 写下的数量是已有能量和对面空位里较小的那个，损耗按这个数来乘。什么时候出手，在 [Link 与枢纽](/mechanisms/links)。

### 浪费只在再生前的最后一拍

`tick` 看这一拍 `Game.rooms` 里的能量源。某一座 `ticksToRegeneration === 1`，就把还剩的 `energy` 加进第三格，第四格加 1。这是再生前的最后一拍。这一行如果还没有，这里会建出来，挖到的能量先记 0。源已经挖光，第三格加上 0，次数仍加 1。其他拍不写浪费。这一拍看不见的房间不扫。

### 账上没有的进出

上面记下的是这些成功意图当时算出的数，再加上源在再生前剩下的能量。`withdraw`、`transfer`、`pickup` 没有包进去。能量从容器、地上或墓碑进到身上，再送进出生点、延伸、塔或存储，这几步都不记。终端发送、市场、实验室反应、creep 的攻击、治疗和拆建筑、`renewCreep`，也没有。矿物收割不加。源重新长出的能量不另记一笔收入。塔这一笔不随距离改变：一次成功就是 **10**，距离改变的是补上的血。

计数留在 `Memory.ledger`。下一只 creep 去哪，仍由上面的角色、换位和桶决定。控制台的 `STATS` 仍是下面这一行。

它是给人看的摘要。`report.run` 的间隔缺省是 **10**。`Game.time` 除以这个间隔，余数不是 0，函数立刻返回。能被 **10** 整除的那一拍才打这一行。`Memory.stats` 每拍都写，里面有这一拍收集到的警报和错误。警报留在统计里。没打这一行的拍，统计照写。

这一行以 `STATS` 起头，后面是一个 JSON。这一行的字段就是这八个：`t`、`cpu`、`b`、`gcl`、`rooms`、`creeps`、`nerr`、`tr`。

| 字段 | 写的是 |
| --- | --- |
| `t` | 这一拍的 `Game.time` |
| `cpu` | `Memory.stats.cpu`，四舍五入到两位小数。`stats.run` 里写成当时的 `Game.cpu.getUsed()` |
| `b` | 打印这一行时读到的 `Game.cpu.bucket` |
| `gcl` | `Memory.stats.gcl`。三个数是 `level`、`progress`、`progressTotal`，取自 `Game.gcl` |
| `rooms` | `Memory.stats.rooms`。各房间已经记下的那一块，整块放进这一行 |
| `creeps` | `Game.creeps` 按 `memory.role` 数出来的各角色数量 |
| `nerr` | `Memory.stats.errors` 里还留着的条数，从 0 到 **10**。新的接在后面，只留最后 **10** 条。这一拍没有新的，旧的还在。数的是留下的条目，不是这一拍新发生了几条 |
| `tr` | `Memory.traceCpu`。统计之前，主循环给 `trace.tick` 和 `trace.run` 计时，四舍五入到三位小数。这是跟踪这一步本拍用掉的 CPU |

孵化、每一间房、外矿、输能、道路、指挥官、袭击旗标、每只 creep 的解脱和角色脚本、换位、能量账、跟踪、统计和报告，各自包在 `utils/errors` 里。一段抛错会记下来，下一整段继续。塔的失败不会取消后面的 creep。一只 creep 的角色脚本抛错，会记下来，后面的 creep 和这行摘要仍会跑。
