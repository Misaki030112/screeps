# 布局与印章

两间房各有一张图。家 W46N8 读 `src/layouts/W46N8.js`，版本 2，由 `tools/plan_v2.py + tools/export_v2.py` 生成。W47N8 的放置顺序在 `src/rooms/w47n8/layout.js`，出生点和枢纽容器的锚点在 `config.js`。`plan.js` 只装入家的那一份。

规划器放到当前控制器等级为止。格子写在图上，表示规划器认得这个位置。人站不站、工业开没开，看旗标和等级。

## 三枚印章

<HomeStamps />

每枚印章五格见方。字母是图案：E 延伸，F 预留站，K 容器的形状，L link 的形状，S 中心。出生方向把整枚印章当成里面。女王和 filler 优先落在里面，其他人优先落在外面。方向怎么排，见 [孵化](/mechanisms/spawn)。

放工地时读 `rcl`。字母和 `rcl` 不一致的地方，下面按 `rcl` 写。

印章 A 的中心 **35,28** 是 RCL1 的出生点。**35,24** 是 RCL2 的容器。**35,26** 的字母是 L，`LINK_PLAN` 把这座 link 放在 RCL8。**35,28** 南面的 **35,29** 不在印章里，那是 RCL8 的第三座出生点。家的路保留名单里有这一格。到 RCL8，规划器要在这里放出生点，冲突的路可以拆。

印章 B 的中心 **30,34** 是 RCL7 的第二座出生点。**34,34** 是 RCL5 的容器。**32,34** 的 L 在 RCL7 写入 link 计划。

印章 C 的字母 S 写在 **30,23**。`rcl` 在 RCL8 把这一格写成延伸。字母 K 写在 **30,27**。容器名单里没有这一格，RCL6 写的是路。**30,25** 的 L 是 RCL8 的 link。

F 共十二格。A 是 34,25、34,27、36,25、36,27。B 是 33,33、31,33、33,35、31,35。C 是 31,26、31,24、29,26、29,24。`STATIONARY_FILL` 是 false。filler 的目标是 0，manager 的目标也是 0。没有 creep 被派去站在 F 上，也没有 creep 被派去当 manager。

格子仍留在 `positions` 里。寻路把十二个 F、管理者 **36,30**、五格升级工和两格矿工写成代价 **20**，这一格还没到 255 才写。升级工和矿工本来就站在自己的格子上。F 和 36,30 付同样的代价，旗标打开时路已经让开。出生方向也靠印章的范围。空站上的城墙要等这面旗打开才算想要。现在城墙盖在已经有的建筑上，或盖在批准的城门上。

女王按印章补延伸。两片怎么分，见 [搬运](/mechanisms/haul)。

## 站位和 link

矿工站 **31,12** 和 **38,32**。矿物矿工是 **41,24**，不在代价 20 的那二十格里。存储 **37,31**，存储门 **36,32**。控制器容器 **30,30**，卸货格 **31,29**。升级工五格是 30,30、31,30、29,30、31,31、29,31。30,30 同时是容器。只数在 [升级](/mechanisms/upgrade)。

**36,30** 挨着存储，也挨着枢纽 link **37,29**。manager 的目标是 0。`noUpgrade` 时，家的搬运工仍会到这一格等。条件在 [搬运](/mechanisms/haul)。

`STATIONARY_FILL` 关着，规划器丢掉 `rcl` 里的 link，改写 `LINK_PLAN`。六座的坐标、等级，以及 400 和每 3 拍，在 [Link 与枢纽](/mechanisms/links)。印章上的三枚 L 对上 35,26、32,34、30,25。枢纽、控制器和源 A 的 link 在印章外面。

容器六只。35,24、30,30、34,34 留下。41,24 跟着矿物线，`RCL6_MINERALS` 开着，所以还在。38,32 从 RCL4 起不再补，源 B 把能量交进旁边的存储。31,12 从 RCL6 起不再补，源 A 的 link 起来之后它只接溢出。已经立着的那一只，要等另一只计划中的容器因为数量上限放不下去，并且一格之内有 link 或存储，才拆。交接见 [搬运](/mechanisms/haul)。

家的塔按等级是 **36,29**，**37,33**，**39,23**，再到 RCL8 的 **40,23**、**31,11**、**32,30**。

`RCL6_MINERALS` 开着。终端 **35,31**、提取器 **40,24** 和矿物容器留在名单里，RCL6 的实验室 **34,22**、**35,21**、**33,21** 也留着。反应见 [实验室](/mechanisms/labs)。矿物见 [矿物](/mechanisms/minerals)。

`RCL7_INDUSTRY` 关着。工厂 **35,30** 和 RCL7 起的实验室从会放的名单里拿掉。人已经放下的实验室或工厂工地，这一圈留下。RCL8 的 powerSpawn **36,33**、nuker **38,23**、observer **33,31** 还在名单上，要到 8 级才轮到。

同文件的 `defense` 是城墙和城门。放建筑的这一圈只读 `rcl`。城墙模块在自己的阶段里读 `defense`，见 [建造、修理和城墙](/mechanisms/build)。`routes` 和 `queenRoute` 记在文件里。寻路和女王都不读它们。

两间房之间的路在 `layouts/w8link.js`。家这一侧跳过已经被非路建筑占上的格子。**34,34** 的容器因此不会被铺成路。

## 家的工地

`managers/layout.js` 每 **25** 拍看一次。等级变了，或上一拍拆过东西，下一拍就再看。一次最多五个工地，城墙另计，见 [建造、修理和城墙](/mechanisms/build)。顺序是出生点、塔、延伸、容器、存储、link、路、城墙、终端、提取器、实验室、工厂、powerSpawn、nuker、observer。

房间里有敌人时，不拆，也不新开路。有延伸工地时，也不新开路。城墙等塔和存储都在，并且这一格是想要的。冲突的路和容器可以拆。出生点、塔、存储、终端、控制器和城墙，这一圈不拆。冲突的延伸要等至少五座不冲突的还在，容量也留得住 **650**，一次拆一座。

计划外的工地会拿掉。人放下的实验室和工厂工地留着。家要保留的路留着。存储已经在时，落在计划城墙格上的城墙工地也留着。

这一拍只要有日志，就作废这间房的路径缓存。拆过东西时，不必再等 25 拍。签名怎么算，见 [移动](/mechanisms/move)。

## W47 的核心

<HubCore />

核心 **34,33** 是路。存储 **35,32**。枢纽 link **32,33**。终端 **33,32**。枢纽容器是配置里的 **33,33**，路表里也有这一格。`ORDER.container` 只有控制器容器 **13,26**。矿物容器 **37,44** 在 `RCL6_MINERALS` 开着时另加。枢纽容器不从那张顺序里来。

**33,34** 的名字是 `RETIRED_HUB_LINK`。它是容器和塔 **33,35** 之间的路。`layoutRun` 拆掉这一格上的 link 工地。已经建成的 link 留着。建筑还在，或工地还在，**32,33** 就不放第二座。文件头仍把 32,33 写成空口袋，那是挪走 33,34 时留下的句子。`ORDER.link` 和 `hubLinkPos()` 现在都是 32,33。

**32,32** 是平地。**34,32** 是路，filler 满载停在这里。让路的代价在 [移动](/mechanisms/move)。条带和灌 link 在 [搬运](/mechanisms/haul)。

出生点是 **15,18**。`ORDER.spawn` 写下以后的三格：**34,30**，**33,30**，**39,30**。34,30 也是城墙保留的空位。五座临时延伸写在出生点旁边：13,16、14,15、16,15、17,16、12,16。换进核心旁的槽，要 34,30 上先有出生点。单独替换还要存储高于 **50000**。迁移记忆走到延伸阶段时，按批拆掉剩下的，不再等这道存储。`moveRun` 在 `Memory.ops.w8move` 缺席时直接返回，15,18 继续当出生点。

四条延伸带的站在路中间：**38,36**、**28,35**、**31,26**、**26,25**。延伸按离核心近的先放，放到这一级的数量为止。两个源、升级工的三格和矿物，表在 [房间与常数](/reference/rooms)。

塔的顺序是 **24,8**、**33,35**、**22,7**，然后才是 34,31、36,31、36,33。按这张顺序往下铺，到这一级的数量就停。RCL7 的塔是三座。还缺第二座出生点 **33,30**，或第三座塔 **22,7** 时，延伸工地让开。

`RCL6_MINERALS` 开着，终端和提取器会放。`RCL6_LABS` 关着，实验室不放。`RCL7_INDUSTRY` 关着，工厂 **35,30**、powerSpawn **36,32**、nuker **34,28**、observer **33,28** 都不放。`HUB_LINK` 开着，32,33 才进入名单。送不送看建筑在不在，见 [Link 与枢纽](/mechanisms/links)。

整张 `ORDER` 要 `Memory.ops.w8layout` 写成 `approved`。键还没有，或写成别的字时，这一拍只补临时延伸和控制器容器。枢纽容器不看批准这道门：到了 3 级、格子还空、房间里已经有出生点，就单独放。这一页不把记忆里的阶段写成已经发生。

W47 每 **20** 拍铺一次。优先级里没有城墙。谁去修封墙，见 [建造、修理和城墙](/mechanisms/build)。空位上的城墙工地会拿掉。城门、34,30 那个空位，以及已经立着的出生点、存储、塔、终端，可以留城墙。看不到己方出生点时不铺。迁移停在建造阶段时，这一拍先停在迁移上。这一圈不调用路径作废。建筑或工地的数量变了，下一拍的签名仍会让旧路失效。见 [移动](/mechanisms/move)。
