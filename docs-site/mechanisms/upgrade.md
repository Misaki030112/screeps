# 升级、地板与 softCap

升级是剩余能量的去处，不是第一优先。控制器快掉级时，会留一只最小的升级工。除此以外，先让存储回到地板之上，再谈加 WORK。

家和 W47 不要混用。家没有 W47 那道 40000 的闩。W47 也不读家的第三只计数。下图里有几处数字碰巧相同，管的却不是同一件事。

<UpgradeFloors />

谁先出生，写在 [孵化](/mechanisms/spawn)。这一页只回答：升级工该有几只，存储要先过高哪一条线。

## 家

没有工地时，底数是 **两只**。RCL6 和 RCL7、预算至少 1550 时，每只是 14 WORK、1 CARRY、2 MOVE。两只一共 28 个 WORK，每拍最多升级 28 点。家加上 W45N8、W45N7，设计净收入大约是 26。后面那份记录里的理想值，用的就是这个 26。28 比 26 大，所以两只满员时，`boundHint` 常常是 `energy`：能量本身不够再养一只满身体，不是搬运断了。

第三只不看「这一拍容器是满的」。容器满一拍就生出 1550 的身体，补能会把存储拉回地板以下，新生的又被当成多余的回收。所以第三只要一段持续的富余。

### 第三只的门

`upExtraTick` 看存储、控制器容器的滑动平均，以及这条件连续成立了多久。滑动平均记在 `room.memory.ctlEma`。孵化在规划目标时用容器里的能量朝旧值靠一靠，不含 link。隔了几拍，下一次按过去的时间补上，尺度大约 **300** tick，结果取整。没有存储时，这个函数清掉闩并直接返回真，那是存储出现之前的路。家已经有存储，用的是下面这道闩。

- 进入：存储不低于地板加 **5000**，并且滑动平均不低于 **1200**，这样连续 **300** tick。第一拍记下起始，过了 300 tick，`room.memory.upExtra` 才写成 1。
- 离开：存储低于地板加 **3000**，或者滑动平均低于 **700**。满足任何一条，闩就清掉，不必再等。
- 已经打开之后，存储可以落到地板加 3000，滑动平均可以落到 700，门还开着。还没打开时，中间断开一拍，连续计数就清零。

殖民地现在把 `Memory.defense.reserveE` 设在 15000。墙的大台阶停住时，女王的地板就是这 15000。进入线是存储不低于 **20000**，离开线是存储低于 **18000**。20000 和 boost 从存储取能量后必须留下的 `STOR_SAFE` 是同一个数。喂不起第三只的时候，也不从同一池子里掏 boost。那道门在 [实验室](/mechanisms/labs)。

`targets` 里，底数是有工地 **1**、没有工地 **2**。门开着，再加上滑动平均除以 700 的整数部分，然后不超过布局里的座位数。RCL8 改成 **1**，身体最多 15 WORK。8 级之后升级不再是进度，只是防止掉级。

1200 除以 700，整数部分是 **1**。没有工地时，2 加 1，是第三只。这就是进入线上这道门的意思。

滑动平均到 **1400**，整数部分是 **2**。没有工地时，同一行会要第四只。五格座位还容得下这只。容器最多装 2000，滑动平均到不了 2100，整数部分到 2 为止，第五只不会从这行里出来。这仍是同一行算术。四只 14 WORK 要 56，设计净收入大约 26，喂不满。

有工地时底数是 1。1200 对应两只，1400 对应三只，同样被座位数封顶。孵化那一拍如果这些工地并不会分到建造工，会按没有工地重算一次升级目标，免得一条没人修的路占掉一只升级工。那是孵化页里的例外，不是这里另写的底数。

门开了也不一定立刻出生。`extraUpReady`：活着的数量已经达到底数，而延伸里的可用能量低于容量减 **1550**，下一只就不开始。没有工地时底数是 2，所以等的是第三只。有工地时底数是 1，第二只也要等。RCL7 的容量是 5600，5600 减 1550 是 **4050**。留给女王继续补延伸，而不是把出生点抽干去换一只升级工。同一拍两座出生点不会各开一只，见孵化里的提前换班。

### 地板，和地板下的那一只

女王的 `storageFloor` 是家这几道门的地板。搬运工整理终端、矿物新趟和「先存银行」各读一道路，见 [搬运](/mechanisms/haul)。

战时平民被暂停时，地板是 **0**，能量改去灌延伸。同一拍孵化把升级目标改成 0；只有掉级时间低于 **20000** 才留 1。地板变成 0，不会因此放行第三只。

平时先取一个 base。某条外矿的防御已经武装时，base 是 **1300**；否则是房间的能量容量。墙的大台阶已经停住时，地板是 base 和 `reserveE` 里较大的那个。1300 和 RCL7 的 5600 都低于 15000，所以按现在的设置，地板就是 **15000**。上面的 20000 和 18000 是从这里加上去的。

台阶还没停时，地板还要加上墙上那笔基金，并且仍然不低于 `reserveE`。基金还在的时候，第三只的门会高于 20000，不是永远钉在 boost 那条线上。

`reserveE` 这个键不在时，墙模块把它当成 **0**。台阶停住的话，女王的地板落到 base，第三只的门跟着挪。家搬运工整理终端时，缺的键按 15000 算。矿物新趟和「先存银行」另看 `defLow`。三道读法写在 [搬运](/mechanisms/haul)。

存储低于防御储备时，还有一道滞后，函数是 `defLowUpgraders`。它只在储备确实把存储压住、或者 `room.memory.upBank` 已经记着的时候才跑。`held` 就是墙的大台阶有没有停住。

台阶**没有**停住：清掉 `upBank`。掉级时间低于 20000 则目标为 1，否则为 **0**。墙还在抽存储，升级让开，只防掉级。

台阶停住了，才用两条带，避免在地板线上每拍生了又拆：

- 进入：存储低于储备减 **500**。15000 的地板上，是低于 **14500**。
- 离开：存储不低于储备加 **2550**。15000 的地板上，是不低于 **17550**。2550 是一只 1550 的身体，再加 1000。离开线如果只比储备高 1000，补这具身体就会把存储抽回进入线以下，新生的马上又被收掉。
- 合着的时候，目标不超过 **1**。留一只，存储贴着地板时控制器不至于黑掉。多出来的去回收。

17550 放开的是平常的两只。第三只还要再等到 20000，并且停满 300 tick。四条线不要并成一条。

### 还会改掉目标的几件事

墙的阶段是 `bank` 或 `roads`，而且 RCL 在 6 到 7：目标再压到最多 1。`roads` 里这一只按 **700** 来长，是 6 WORK、1 CARRY、1 MOVE，把产量让给建造。

`noUpgrade` 为真时，目标写成 0。修路阶段、终端或实验室或萃取器还有工地、城墙圈还没合上，或者最低一截的有效命中还没到 100000，都会这样。掉级时间低于 20000 时，这道 0 不会写下。修路阶段那时留下上面那只 700 的。这里只说明这些阶段会改升级工的数。

### 座位

布局里的座位是 **30,30**、**31,30**、**29,30**、**31,31**、**29,31**。30,30 同时是控制器容器。link 在 **30,31**，不占座位。只数公式用这五格做上限。

升级工走到自己的座位就坐下，从旁边的 link 或容器取能量，不走回存储。让它们回存储，窄路会被对向的人堵死，控制器旁反而更空。家的控制器 link 低于 **400** 就接收。搬运工把容器低于 **1000** 的那一格排到前面。传送条件在 [Link](/mechanisms/links)，搬运顺序在 [搬运](/mechanisms/haul)。

换班不在这里重复。家的升级工在寿命降到身体长度乘 3 再加 30 以下时，不再算进「还缺不缺」，见 [孵化](/mechanisms/spawn)。

## 只记录，不改孵化

`managers/upgfeed.js` 只写家的 `Memory.ops.upgFeed`，每 **5** tick 一次。它不孵人，也不搬 link，也不写 W47。标签按顺序取第一条成立的，所以同一拍不会叠两个原因。

| 标签 | 什么时候 |
| --- | --- |
| `war` | 平民暂停开着 |
| `remote_pause` | W45N8 或 W45N7 不在 SAFE。前者按 6.86、后者按 4.54 计入暂停，再除以 1.072，从理想的 26 里减去 |
| `floor_bank` | `upBank` 还合着。这是上面 14500 / 17550 的滞后，不是容器空了 |
| `ctl_starved` | 有升级工身上的能量不多于自己的 WORK 数，link 没有能量（或没有这座 link），容器也是 0，而且滑动平均低于 **400** |
| `thin_surplus` | 存储比地板高出的部分不到 **1000**，并且滑动平均低于 **700**。还没进 `upBank`，才会落到这里 |
| `waiting_feed` | 同样有人空着手、电池也空，但前面几条都不成立。这一拍没送到，不是地板闩 |
| `ok` | 以上都不是 |

`boundHint` 另算，不参与上面的顺序。活着的 WORK 多于暂停调整后的理想值，记 `energy`；还有 WORK 但没超过，记 `ok`；一个 WORK 都没有，记 `none`。两只 14 WORK 是 28，理想值大约 26，所以和平时期满员常常是 `why` 为 `ok`、`boundHint` 为 `energy`。这是设计上的能量边界，不是运输故障。

记录里的 `allowExtra` 是地板加 5000 那个数。门开没开看 `upExtra`。`upExtraSince` 是这一轮连续计数从哪一 tick 开始，还没开始时是 0。`idealAdj` 是扣掉暂停外矿之后的理想净收入，保留一位小数，只作提示。

## W47 的三道水位

W47 把「少生升级工」拆成三件事。出生目标由 `upgTarget` 算，多出来的人由旁边的回收名单收。能量软顶管的是停车和封墙。若把「存储过了 25000」直接当成可以加人，link 喂不饱，能量会掉回去。

### 节流：15000 和 20000

出生目标先问 `energyBank`。它在两件事上为真：房间正在做出生点搬迁，而且存储加上枢纽容器还不到 **11000**；或者 `leanBank` 还合着。这两件都不是 40000 的闩。

为真时，存储低于 **15000**：掉级时间小于 **20000** 才要 1 只，否则要 **0**。不低于 15000，要 **2**。然后再套工地上限。

`leanBank` 自己更窄。RCL 低于 7，或者人把 `Memory.ops.w8leanBank` 设成 false，它就是假。第二座出生点或第三座塔还缺，它也是假，改走下面的缺口。终端或矿物容器还没立起来时，它不按 20000 松开，节流一直留着，40000 的闩不会被问到。

两边都在、而且曾经松开之后：存储到 **20000** 松开；要重新合上，得先低于 **15000**。中间的浅坑，一次外矿防御抽走几千，不会让「可以升级」和「必须存钱」来回翻。合着、并且存储已经不低于 15000 时，出生目标是 2，不是 3。低于 15000 则是上面的 0 或 1。回收在这一段更宽，见后文。

### 缺一座出生点或一座塔

`dayofMiss` 看计划顺序里的第二座出生点 **33,30**，和第三座塔 **22,7**。缺任何一座，而 `energyBank` 又没有先把目标抢走时，出生目标是 **1**。本地威胁和 40000 的闩都排在这条后面。

回收名单不读这个缺口。没有工地时，已经在站上的人仍按闩留在 2 或 3。工地会另把回收收成 1，那是工地，不是这座还没盖好的建筑。

### 能量软顶：22000 和 25000

`softEnergyCap` 是软顶的能量那一半。

- 存储不低于 **25000**：清除。
- 已经清除，而且存储仍不低于 **22000**：保持清除。要重新武装，得低于 22000。
- 已经武装，存储还没回到 25000：保持武装。

`softCap2` 是这半边，或本地威胁，有一边为真即可。它让搬运停车和封墙不要在 25000 上来回抖。它不写升级工只数。闩合不合、节流开没开，都不看它。

### 升级闩：40000 和 30000

`energyBank` 为假、出生点和塔都在、又没有本地威胁时，目标是 **2**。存储连续不低于 **40000** 满 **500** tick，`Memory.ops.w8up` 合上，目标变成 **3**。第一拍记下起始，经过 500 tick 才合。中间掉到 40000 以下，只要还没合上，连续计数就清零。已经合上之后，可以落到 30000，门还关着；低于 **30000** 才打开，回到 2。

软顶清除的那一拍，不会按存储多出来的能量再加人。和平时期的上限是 3。存储只是摸过高线、没停满 500 tick，目标仍是 2。某一天有没有停满，以 [现状](/now) 那份快照为准。软顶若还开着，可以只是威胁窗口的尾声。

### 本地威胁

`threatSoft` 就是本地窗口还在不在 **1500** tick 里。看的是这间房和 W47N7。升级工的软限制跟这扇窗。能把封墙抬起来的信号不止这一条，那些不压升级工只数。窗口怎么分，写在 [防御](/mechanisms/defense)。

窗口没过期时，即使闩已经合上，目标仍是 **2**。窗口结束，才回到闩的 2 或 3。

封墙若还低于威胁地板的九成，出生点会先按修理要 1 或 2 只，不走上面的目标。那是补命中。墙的规则不在这一页展开。

### 回收和出生可以差一只

回收问的是 `leanBank`，不是完整的 `energyBank`。RCL7、节流没合上时，本地威胁还在、或者闩还没合上，就留 **2**，否则留 **3**。然后再套工地上限。

和平时期、没有工地、没有本地威胁、节流也没合上，出生和回收是同一幅图：2，闩合上之后是 3。三处会对不上，读的时候不要当成算错：

- 节流合着、存储低于 15000、掉级时间又不小于 20000：出生要 **0**，回收仍留 **1**。人还在，就不为了「目标是 0」把最后一只送去回收。
- 缺出生点或塔：出生要 1，回收不因此把其他人收掉。
- 只因搬迁银行还没满、而节流本身是关的：出生走 0、1 或 2，回收仍按和平时期的 2 或 3。存储已经低于 15000 时，节流通常自己就是合着的，这一条要和上一处的「留 1」一起看。

节流合着、存储不低于 15000 时，两边都是 2。有工地，再一起压到 1。

### 工地

RCL7 看见任何己方工地，出生和回收都收成最多 **1**。低于 RCL7 不动。工地清完，不重新抽一只数：闩还合着就是 3，没合上就是 2，本地威胁仍是 2，节流的带子也还是原来的带子。不会从 1 直接跳到很多只。

## 控制器旁边

W47 的升级工站在 **12,25**、**14,26**、**14,27**。容器在 **13,26**，link 在 **13,25**。搬运卸货用 **13,27** 和 **12,27**，不进这三格。按容量生的身体是 1 CARRY、2 MOVE，再堆最多 10 个 WORK。1 个 CARRY 的容量是 50，容器空了也留在座位上，不走回存储，也不去源旁边的堆里捡。去捡的话，窄路上会和送能量的人迎面堵住。

枢纽 link 在 **32,33**。到 13,25，横着差 19，竖着差 8，冷却取较大的那个，是 **19**。一次最多送 800，扣掉 3% 的损耗；若每次冷却都送满，净输送大约 **41**。实际还要控制器 link 低于 400、枢纽里至少 200，所以不是每拍都有这 41。三只满预算是 30 个 WORK，这条管子在满载时盖得住。四到六只盖不住，座位也不够。所以 25000 一清除，不能当成可以再放一排升级工。数量先被闩住。传送条件在 [Link](/mechanisms/links)。

家的座位和「不回存储」写在上面。两间房是同一条原则：升级工吃控制器旁边已经送到的能量。

## 为什么地板比「能升级就升级」重要

两个源各再生 10，外矿再加一截，扣掉身体维持、道路衰减和防御，剩下的才是升级。家的设计净收入大约 26，就是扣完之后的数。把这点剩余全部堆进控制器，进度好看，存储没有缓冲。一只远程防御身体从 1300 到 RCL7 的 5600，从延伸里抽，抽完还要补回去。缓冲没了，下一次入侵者会让矿停、升级停、塔也空。

**15000** 是这次缓冲的操作数。它低于 boost 要留下的 20000，也低于 W47 愿意多养一只升级工的 40000。家的 18000 和 20000 挂在自己的地板上。W47 的 15000 与 20000、22000 与 25000、30000 与 40000 是另外三道门。不是一根可以从 15000 滑到 40000 的滑杆。
